# Лабораторная работа 1 — Python Core

Первый этап: проверка одной сдачи и создание неизменяемой модели. Реализованы `Submission`, `AIDeclaration`, структурированные ошибки и строгий разбор JSON по схеме версии 1.

## Установка

Нужен Python 3.12 или новее. Команды выполняются из папки проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install ".[dev]"
.\.venv\Scripts\python.exe -X utf8 -m pytest -q
.\.venv\Scripts\python.exe -X utf8 examples/validate_one.py
```

Последняя команда проверяет искусственную запись `data/submission.json` и выводит её поля. При ошибке JSON или схемы она выводит `code`, `field`, `message` и возвращает код завершения 1. Исходный код из поля `code` не исполняется.

## Что проверяется

- Обязательные поля присутствуют, неизвестных полей нет.
- Версия схемы — целое число 1; `True` и строка `"1"` не допускаются.
- Идентификаторы — непустые строки.
- Время задано в ISO-формате с часовым поясом.
- Хотя бы одно из полей `text` и `code` непустое после проверки пробелов.
- `used` и `verified_by_student` — настоящие `bool`.
- При `used=True` указаны непустые `tool` и `purpose`.
- Повторяющиеся ключи JSON и константы NaN/Infinity отклоняются.

Пробелы и переводы строк исходника сохраняются. Parser создаёт новую модель и не меняет входной словарь. Обычное присваивание полям модели и вложенной декларации запрещено через `frozen=True`; сама аннотация типа ничего не проверяет во время выполнения.

## Структура

```text
src/school_lab/
    models.py             модели Submission и AIDeclaration
    errors.py             ошибка SubmissionError
    parsing.py            разбор JSON и проверка схемы
tests/
    conftest.py           отдельный пример данных для каждого теста
    test_parsing.py       проверки parser и неизменяемости моделей
data/submission.json      искусственная запись для демонстрации
examples/validate_one.py  запуск проверки одной записи
docs/API.md               краткое описание входов и выходов
```

`decode_json(text)` разбирает формат JSON. `parse_submission(raw)` проверяет поля и возвращает `Submission`. Ошибки содержат код, имя проблемного поля и объяснение. Модель `Submission(...)` хранит переданные значения; для проверки внешних данных нужно обращаться к parser.
